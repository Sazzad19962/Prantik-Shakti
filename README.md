# Prantik-Shakti

প্রান্তিক শক্তি লিমিটেড (Prantik Shakti Limited)-এর বাংলা ওয়েবসাইট ও অ্যাডমিন প্যানেল।

## এটি কী

এটি একটি ডায়নামিক (Node.js) ওয়েবসাইট। সাইটের **সব লেখা, ছবি, নোটিশ, কোর্স, সেবা, নেতৃত্ব, যোগাযোগ ও নিবন্ধন তথ্য** ওয়েব-ভিত্তিক অ্যাডমিন প্যানেল (`/admin`) থেকে পরিবর্তন করা যায় — কোড না ছুঁয়েই। সংরক্ষণের সঙ্গে সঙ্গে পাবলিক সাইটে পরিবর্তন দেখা যায়।

- **পাবলিক সাইট:** আগের স্থির `index.html`-এর হুবহু নকশা (রং, ফন্ট, লাইট/ডার্ক থিম, মোবাইল মেনু, “ঠিকানা কপি” বোতাম)। পাতা সার্ভারেই তৈরি হয়, তাই সার্চ ইঞ্জিন সব লেখা দেখতে পায়। নতুন সংযোজন: কোর্স তালিকা, নোটিশ বোর্ড ও নোটিশের আলাদা পাতা (`/notices/:id`), গ্যালারি (ছবি না থাকলে লুকানো), অবকাশ কেন্দ্রের ছবি ও বুকিং তথ্য, এবং যোগাযোগ ফর্ম।
- **অ্যাডমিন প্যানেল:** বাংলা ইন্টারফেস, মোবাইলেও ব্যবহারযোগ্য। ড্যাশবোর্ড, সাইট সেটিংস, হিরো ও স্তম্ভ, পরিচিতি ও তথ্য-রেখা, নেতৃত্ব, সেবা, প্রশিক্ষণ ও কোর্স, বৈদেশিক কর্মসংস্থান, অবকাশ কেন্দ্র, সাংগঠনিক কাঠামো, নোটিশ, গ্যালারি, অংশ ও মেনুর ক্রম, বার্তা (এনকোয়ারি), মিডিয়া লাইব্রেরি, ব্যবহারকারী, কার্যক্রমের লগ, ব্যাকআপ ও রিস্টোর।
- **স্টোরেজ:** `MONGODB_URI` দেওয়া থাকলে MongoDB (যেমন MongoDB Atlas); না থাকলে লোকাল JSON ফাইল (`data/content.json`, `data/state.json`, `data/uploads/`)। প্রথম চালুতে স্টোর খালি থাকলে `data/seed.json` থেকে বর্তমান ওয়েবসাইটের সব বিষয়বস্তু স্বয়ংক্রিয়ভাবে যুক্ত হয়।

> দ্রষ্টব্য: সাইটটি এখন Node.js সার্ভারে চলে, তাই GitHub Pages-এ আর প্রকাশ করা যাবে না। নিচের Render নির্দেশনা অনুসরণ করুন।

## লোকাল কম্পিউটারে চালানো

প্রয়োজন: Node.js ২০ বা তার পরের সংস্করণ।

```bash
npm install
npm start
```

তারপর ব্রাউজারে খুলুন:

- ওয়েবসাইট: <http://localhost:3000>
- অ্যাডমিন প্যানেল: <http://localhost:3000/admin>

ডেভেলপমেন্টে `ADMIN_PASSWORD` সেট না থাকলে ডিফল্ট লগইন **`admin` / `admin123`** — অ্যাডমিন প্যানেলে একটি সতর্কবার্তাও দেখাবে। লোকালে ডেটা `data/` ফোল্ডারে থাকে (git-এ যায় না; শুধু `data/seed.json` রিপোজিটরিতে আছে)। সব মুছে নতুন করে শুরু করতে `data/seed.json` বাদে `data/`-এর বাকি সব ফাইল মুছে দিন।

পরীক্ষা (টেস্ট) চালাতে:

```bash
npm test
```

## পরিবেশ-চলক (Environment variables)

নমুনা: `.env.example`। লোকালে প্রয়োজনে টার্মিনালে সেট করুন (যেমন `ADMIN_PASSWORD=... npm start`)।

| চলক | প্রয়োজন | বিবরণ |
|---|---|---|
| `NODE_ENV` | production-এ `production` | নিরাপদ কুকি (Secure), HSTS ও কঠোর যাচাই চালু করে |
| `PORT` | না | সার্ভারের পোর্ট (Render নিজেই দেয়), ডিফল্ট 3000 |
| `MONGODB_URI` | production-এ হ্যাঁ | MongoDB Atlas-এর সংযোগ স্ট্রিং। না থাকলে লোকাল JSON ফাইল ব্যবহৃত হয় |
| `MONGODB_DB` | না | ডাটাবেসের নাম; না দিলে URI-তে থাকা নাম, নইলে `prantik_shakti` |
| `ADMIN_USERNAME` | না | প্রধান অ্যাডমিনের (মালিক) ব্যবহারকারীর নাম, ডিফল্ট `admin` |
| `ADMIN_PASSWORD` | production-এ হ্যাঁ | প্রথম চালুতে মালিক অ্যাকাউন্ট এই পাসওয়ার্ডে তৈরি হয়। production-এ এটি না থাকলে এবং কোনো ব্যবহারকারী না থাকলে সার্ভার চালু হবে না |
| `ADMIN_RESET_PASSWORD` | না | `1` দিলে চালুর সময় মালিকের পাসওয়ার্ড `ADMIN_PASSWORD` অনুযায়ী রিসেট হয় (পাসওয়ার্ড ভুলে গেলে)। কাজ শেষে সরিয়ে দিন |
| `SESSION_SECRET` | production-এ হ্যাঁ | লগইন কুকি স্বাক্ষরের গোপন কী (কমপক্ষে ৩২ অক্ষর)। production-এ না থাকলে সার্ভার চালু হবে না |
| `SESSION_TTL_HOURS` | না | লগইন কতক্ষণ বহাল থাকবে, ডিফল্ট ১২ ঘণ্টা |
| `DATA_DIR` | না | লোকাল JSON ব্যাকএন্ডের ফোল্ডার, ডিফল্ট `./data` |

গুরুত্বপূর্ণ: মালিকের পাসওয়ার্ড শুধু **প্রথম চালুতে** `ADMIN_PASSWORD` থেকে নেওয়া হয়। পরে পাসওয়ার্ড বদলাতে অ্যাডমিন প্যানেলের “ব্যবহারকারী” পাতা ব্যবহার করুন (অথবা `ADMIN_RESET_PASSWORD=1`)।

## Render + MongoDB Atlas-এ প্রকাশ (ধাপে ধাপে)

### ১. MongoDB Atlas প্রস্তুত করুন

1. <https://cloud.mongodb.com>-এ লগইন করে একটি Cluster খুলুন (ফ্রি M0 যথেষ্ট)।
2. **Database Access** → *Add New Database User* — একটি ব্যবহারকারী ও শক্তিশালী পাসওয়ার্ড তৈরি করুন (Read and write to any database)।
3. **Network Access** → *Add IP Address* → `0.0.0.0/0` (Render-এর IP স্থির নয়)। পাসওয়ার্ড শক্তিশালী রাখুন।
4. **Database** → *Connect* → *Drivers* — সংযোগ স্ট্রিং কপি করুন এবং `<password>` বদলে দিন। শেষে ডাটাবেসের নাম যোগ করতে পারেন, যেমন:
   `mongodb+srv://psl_user:PASSWORD@cluster0.xxxxx.mongodb.net/prantik_shakti?retryWrites=true&w=majority`

### ২. Render-এ ওয়েব সার্ভিস তৈরি করুন

1. এই রিপোজিটরি GitHub-এ পুশ করা থাকতে হবে।
2. <https://dashboard.render.com> → **New** → **Blueprint** → রিপোজিটরি নির্বাচন করুন। Render `render.yaml` পড়ে নিজে থেকেই সার্ভিস তৈরি করবে (`npm ci` → `npm start`, হেলথ চেক `/healthz`)।
   - বিকল্প: **New → Web Service** → Build Command `npm ci`, Start Command `npm start`।
3. **Environment** অংশে বসান:
   - `MONGODB_URI` = ধাপ ১-এর সংযোগ স্ট্রিং
   - `ADMIN_PASSWORD` = শক্তিশালী পাসওয়ার্ড (কমপক্ষে ১২ অক্ষর)
   - `ADMIN_USERNAME` = পছন্দের নাম (ডিফল্ট `admin`)
   - `SESSION_SECRET` = Blueprint নিজেই র‍্যান্ডম মান তৈরি করে; হাতে তৈরি করলে কমপক্ষে ৩২ অক্ষরের র‍্যান্ডম স্ট্রিং দিন
   - `NODE_ENV` = `production`
4. **Deploy** করুন। লগে “প্রাথমিক বিষয়বস্তু (seed.json) যোগ করা হয়েছে” ও “মালিক ব্যবহারকারী … তৈরি হয়েছে” দেখা যাবে।
5. `https://<আপনার-সার্ভিস>.onrender.com/admin`-এ গিয়ে লগইন করুন এবং “ব্যবহারকারী” পাতা থেকে প্রয়োজনে পাসওয়ার্ড পরিবর্তন করুন।
6. (ঐচ্ছিক) নিজস্ব ডোমেইন: Render → Settings → *Custom Domains*।

> সতর্কতা: Render-এর ফাইল সিস্টেম স্থায়ী নয়। `MONGODB_URI` ছাড়া production-এ চালালে রিডিপ্লয়/রিস্টার্টে সব পরিবর্তন ও আপলোড হারিয়ে যেতে পারে (সার্ভার লগে সতর্কবার্তা দেখাবে)।
>
> ফ্রি প্ল্যানে কিছুক্ষণ ব্যবহার না হলে সার্ভিস ঘুমিয়ে যায়; প্রথম ভিজিটে কয়েক সেকেন্ড দেরি হতে পারে।

## অ্যাডমিন প্যানেল ব্যবহার — সংক্ষেপে

- **ড্যাশবোর্ড:** অপঠিত বার্তা, নোটিশ, সেবা, কোর্স, ছবি ইত্যাদির সংখ্যা ও সাম্প্রতিক পরিবর্তন।
- **সাইট সেটিংস:** প্রতিষ্ঠানের নাম, ব্রাউজার শিরোনাম ও বিবরণ, লোগো, যোগাযোগ (ঠিকানা, ফোন, ই-মেইল, মূল সংস্থার লিংক, অফিস সময়, মানচিত্র লিংক, যোগাযোগ ফর্ম চালু/বন্ধ), ফুটার, দ্রুত লিংক এবং নিবন্ধন তথ্য (RJSC নম্বর, ট্রেড লাইসেন্স, ই-টিআইএন)।
- **তালিকাভিত্তিক অংশ** (স্তম্ভ, তথ্য-রেখা, তথ্য সারণি, নেতৃত্ব, সেবা, কোর্স, ধাপ, অবকাশ কেন্দ্র, মডিউল, নোটিশ, গ্যালারি): “+ নতুন” দিয়ে যোগ, “সম্পাদনা”, “মুছুন”, ↑/↓ দিয়ে ক্রম পরিবর্তন, এবং “লুকান/প্রকাশ করুন” দিয়ে দৃশ্যমানতা।
- **সেবা:** শিরোনাম, বিবরণ, ঐচ্ছিক স্ট্যাটাস ট্যাগ (যেমন “লাইসেন্স প্রক্রিয়াধীন”) এবং বিদ্যমান আইকন সেট থেকে আইকন বাছাই।
- **নোটিশ:** তারিখ, বিস্তারিত, ঐচ্ছিক PDF/ছবি সংযুক্তি; “প্রকাশিত” টিক না দিলে খসড়া থাকে। নতুন নোটিশ আগে দেখায়।
- **গ্যালারি:** একসঙ্গে একাধিক ছবি আপলোড, পরে ক্যাপশন যোগ। ছবি না থাকলে সাইটে অংশটি লুকানো থাকে।
- **অংশ ও মেনুর ক্রম:** কোন অংশ দেখাবে, কোন ক্রমে, এবং উপরের মেনুতে কোনটি কী নামে থাকবে।
- **বার্তা:** যোগাযোগ ফর্ম থেকে আসা বার্তা; পঠিত/অপঠিত চিহ্নিত করা ও মুছে ফেলা।
- **মিডিয়া লাইব্রেরি:** সব আপলোড (JPG, PNG, WEBP, PDF; প্রতিটি সর্বোচ্চ ৫ MB)। কোনো ফাইল সাইটে ব্যবহৃত হলে তা মোছা যায় না। ছবি বদলালে পুরোনো ফাইল লাইব্রেরিতে থেকে যায় — প্রয়োজনে এখান থেকে মুছুন।
- **ব্যবহারকারী:** নিজের পাসওয়ার্ড পরিবর্তন; মালিক (প্রধান অ্যাডমিন) নতুন অ্যাডমিন তৈরি ও মুছতে পারেন।
- **কার্যক্রমের লগ:** কে, কখন, কী পরিবর্তন করেছেন (লগইন ও ব্যর্থ লগইনসহ)।

## ব্যাকআপ ও রিস্টোর

- **ব্যাকআপ:** অ্যাডমিন → “ব্যাকআপ ও রিস্টোর” → “ব্যাকআপ ডাউনলোড করুন”। একটি JSON ফাইলে পুরো বিষয়বস্তু, চাইলে ছবি/PDF ও বার্তাসহ, ডাউনলোড হবে। মাসে অন্তত একবার এবং বড় পরিবর্তনের আগে ব্যাকআপ রাখুন।
- **রিস্টোর:** একই পাতায় ব্যাকআপ ফাইল আপলোড করুন। ফাইলটি প্রথমে সম্পূর্ণ যাচাই হয়; কোনো ত্রুটি থাকলে কিছুই পরিবর্তন হয় না। রিস্টোরে বর্তমান বিষয়বস্তু প্রতিস্থাপিত হয় ও ব্যাকআপের ছবি/ফাইল যুক্ত হয়; ব্যবহারকারী ও লগইন অপরিবর্তিত থাকে।
- **অতিরিক্ত সুরক্ষা:** MongoDB Atlas-এর নিজস্ব ব্যাকআপ/স্ন্যাপশট সুবিধাও ব্যবহার করা যায়। লোকাল মোডে পুরো `data/` ফোল্ডার কপি করে রাখলেই ব্যাকআপ হয়।

## নিরাপত্তা (সংক্ষেপে)

- অ্যাডমিনের লেখা সবকিছু HTML-এস্কেপ করে দেখানো হয় (XSS প্রতিরোধ); লিংকে শুধু `https://`, `mailto:`, `tel:`, `#…` ও `/…` অনুমোদিত।
- পাসওয়ার্ড scrypt দিয়ে হ্যাশ করা; লগইন কুকি HttpOnly, SameSite=Lax, production-এ Secure, এবং `SESSION_SECRET` দিয়ে স্বাক্ষরিত; সেশন সার্ভারে সংরক্ষিত (লগআউটে সত্যিই বাতিল হয়)।
- প্রতিটি পরিবর্তনের অনুরোধে CSRF টোকেন ও Origin যাচাই; লগইনে বারবার ভুল করলে ১৫ মিনিটের জন্য লক।
- আপলোডের ধরন ফাইলের ভেতরের বাইট দেখে যাচাই হয় (শুধু JPG, PNG, WEBP, PDF; সর্বোচ্চ ৫ MB)।
- Content-Security-Policy (শুধু নিজস্ব স্ক্রিপ্ট ও Google Fonts), X-Frame-Options ইত্যাদি নিরাপত্তা হেডার।
- যোগাযোগ ফর্মে হানিপট (স্প্যাম-ফাঁদ) ও প্রতি IP থেকে ১৫ মিনিটে সর্বোচ্চ ৫টি বার্তার সীমা।
- কোনো গোপন তথ্য রিপোজিটরিতে নেই; `.env` ফাইল git-এ যায় না।

## ফাইল কাঠামো

```
server.js              সার্ভার চালু করার ফাইল
src/config.js          পরিবেশ-চলক পড়া
src/app.js             Express অ্যাপ, seed ও মালিক অ্যাকাউন্ট তৈরি
src/schema.js          বিষয়বস্তুর কাঠামো ও যাচাই (অ্যাডমিন ফর্মও এখান থেকে তৈরি)
src/security.js        পাসওয়ার্ড হ্যাশ, কুকি স্বাক্ষর, রেট লিমিট, নিরাপত্তা হেডার
src/media.js           আপলোড যাচাই
src/store/             MongoDB ও লোকাল JSON স্টোরেজ
src/routes/            পাবলিক ও অ্যাডমিন রাউট
src/views/             পাবলিক সাইট ও অ্যাডমিন প্যানেলের HTML
public/                CSS ও JavaScript
data/seed.json         প্রাথমিক বিষয়বস্তু (আগের ওয়েবসাইট থেকে)
test/                  স্বয়ংক্রিয় পরীক্ষা (npm test)
render.yaml            Render Blueprint
```
